HumanFrame Framework

The software behind the interaction.

One evolving framework for bringing applications, robot capabilities, and research ideas together.

A useful robot needs a system that lets new ideas run on it. HumanFrame connects application development, on-robot execution, and deployment as parts of the same engineering effort.

From an application to a physical experience.

The intended architecture gives each layer a clear responsibility.

  1. Research applicationDefine the experience
  2. HumanFrame SDKUse supported capabilities
  3. HumanFrame RuntimeCoordinate execution
  4. Interactive robotConnect with people

HumanFrame Platform supports application packaging, deployment, and monitoring around this workflow.

A system overview, rather than a claim that every interface is complete. Prototype foundations exist; integration and supported capabilities are expanding.

Clear responsibilities

Shared foundations. More room for custom work.

Researchers should be able to concentrate on application behavior without recreating every connection to the robot.

HumanFrame Runtime
The on-robot software layer coordinates application execution and supported device capabilities. Early runtime prototypes provide a foundation for managing applications and connecting them with hardware services.
HumanFrame SDK
Development tools and interfaces are being built to make supported robot behavior more reusable and consistent. Early tools exist; broader standardized interfaces are under development, and a public SDK release has not been announced.
HumanFrame Platform
The supporting application environment includes prototype packaging, validation, deployment, and monitoring workflows. Full integration between the web platform and the developing robot is ongoing.
Research applications
Custom experiences define the prompts, responses, visuals, and interaction logic for a specific activity. Reminiscence is one application being adapted to the HumanFrame foundation.

A developer's path

Create. Run. Refine.

The goal is a consistent route from a research idea to an application running on a physical robot.

Define the experience

Write application behavior around the prompts, content, and supported capabilities your activity needs.

Prepare the application

Package compatible code and resources, then validate the application before installation.

Run on the robot

Use the runtime to execute the application and connect it with supported hardware functions.

Inspect and improve

Review execution information and logs to guide the next application revision.

Local application packaging, installation, execution, and health checks have been demonstrated in development prototypes. The complete web-to-robot experience is still being integrated.

Systems engineering for interaction

The details matter because the experience does.

Coordinating audio, visual feedback, application behavior, and physical hardware takes careful integration. Our framework is being built as a shared foundation for that work.

Current development builds on tested camera and audio capture, runtime execution, and local deployment prototypes. Integrated conversation, expressive displays, wider application interfaces, and planned mobility require further development and validation.
